# uv environment setup

## Goal

Provide a Conda-free Linux/Windows installation entrypoint using uv and Python
3.11. Existing Conda setup remains supported. Do not modify sorting algorithms.

## Design

- `scripts/setup_uv.py` creates/reuses repository `.venv`, then uses `uv pip`
  against that environment explicitly, even when Conda is active.
- `requirements.uv.txt` installs the project editably with notebook/dev extras,
  pins the reference numerical stack, declares vendored Kilosort dependencies,
  and retains Git Phy and nelpy plus neuro-analysis-py for Phy summaries.
- Avoid exporting unrelated Conda packages and duplicate CUDA runtimes. uv resolves
  transitive dependencies. Keep torch 2.9.1/torchvision 0.24.1; default backend
  cu130 preserves the Linux choice, with explicit cpu/cu126/cu128 alternatives.
- Verify dependency consistency and imports/source path after installation.
- Retain the checkout for source assets and vendored sorter. Local and Slurm
  workers already launch sys.executable, so the virtualenv propagates naturally.
- This is uv's pip interface, not a universal uv.lock workflow. No unverified
  lockfile will be manufactured. Git nelpy remains upstream's unpinned URL.

## Verification

Test environment targeting, reuse, fail-fast missing tools/source, platform paths,
and verification commands without network. Parse every requirement and check
vendored dependency coverage. Attempt actual uv availability/install validation;
report network or tool limitations. Update README and change log.
